# AGENTS.md

## Project

Browser demo "Корованы: Тёмная дорога" — a Daggerfall-like first-person raycaster where you rob caravans. Vanilla JS ES modules + Canvas 2D, no build step, no npm dependencies (`npm install` is never needed), no bundler/linter/typecheck/CI. All art and audio are procedural.

User-facing text, comments and `README.md` are Russian. Keep new strings in Russian.

## Commands

- `npm start` — dev server on port 8000 via `scripts/serve.mjs`, which sends `Cache-Control: no-store`. Open `http://localhost:8000`.
- `npm run start:python` — legacy `python -m http.server 8000`. **It sends no cache headers**, so Chrome keeps stale ES modules (`304 Not Modified`) and you debug code that isn't running. Prefer `npm start`.
- `npm run verify` — `npm run check && npm test`; the only real gate, run it before committing.
- `npm run check` — `node --check` on every `.js`/`.mjs`/`.cjs` in `src/`, `tests/`, `scripts/`, `electron/` (hardcoded dir list in `scripts/check.mjs`; new dirs must be added there).
- `npm test` — `node --test` (auto-discovers `tests/*.test.js`). One file: `node --test tests/systems.test.js`.

### Desktop build (Electron)

- `npm install` — **required for the desktop build only.** This is the one exception to "no npm dependencies": Electron cannot exist without it. The browser build still needs nothing.
- `npm run electron` — runs the game in an Electron window.
- `npm run dist` — builds `dist/Corovans-win32-x64/Corovans.exe` via `electron-packager` (asar, win32-x64). ~250 MB folder.
- `npm run icon` — regenerates `electron/icon.png` and `electron/icon.ico` from `scripts/make-icon.mjs` (raw PNG/ICO written by hand, no image tooling).
- `electron/main.cjs` serves the game over a **custom `app://` protocol**. `win.loadFile()` does **not** work: Chromium blocks ES modules on `file://` by CORS and the window stays blank. Do not "simplify" this to `loadFile`.
- `webPreferences.sandbox` is **false** on purpose — with `sandbox: true` the renderer dies with `Renderer process launch-failed` and no window appears. `contextIsolation: true` + `nodeIntegration: false` carry the security here.
- The window uses `useContentSize: true` and 1280×720 so the canvas buffer maps 1:1; `applyCanvasScale` then reports scale 1.

- `?debug=1` (any value works) exposes `window.__corovans`: `game`, `run`, `profile`, `ui`, `input`, `player`, `world`, `renderer`, `saveCheckpoint`, `debugStyle`.

ES modules require HTTP; `index.html` over `file://` fails. In Electron that is solved by the `app://` protocol (see above), not by `loadFile`. There is no browser test runner, so rendering/UI/input changes can only be validated by playing the page.

`main.js` logs `[corovans] build <stamp>` and exposes `window.__corovans.build` under `?debug=1`. If the stamp is not the one you just wrote, the browser is serving a cached module — reload hard before debugging behavior.

## Architecture

- `src/main.js` — only entrypoint. Owns the mutable `game` runtime object, the rAF loop, interactions, trade, contracts wiring, checkpoints. `run` is the persisted run state; `game` is throwaway runtime state. Don't mix them.
- `src/run.js` — run creation, snapshot/restore, `canCheckpoint`, acts, soft-death penalty. All save logic is testable here; `src/save.js` is the only module touching `localStorage`.
- `src/world.js` — 200×200 tile map built in code, props, actors, collision, LOS, archetype layouts (`CAMP_LAYOUTS`), map zones (`ZONES`, `SPAWN`, `MERCHANT_POS`, `COURTESAN_POS`, `WAGON_BASE`). `makeActor()` is the single actor factory; `spawnCamp(world, tier, tuning)` rebuilds the camp. Map coordinates are code, not data. `hasPath()` does a tile flood-fill — use it before moving any building. **`ZONES` are absolute map coordinates, but the village build code still uses the old 120×120 numbers and `fillRect`/`addProp` shift them by `V = 40`.** Mixing the two systems silently puts buildings in the wrong place — use `fillAbs`/`addPropAbs` for anything expressed in absolute coordinates. `world.tallTiles` (`"x,y" → height multiplier`) makes the cathedral and town hall taller than a fence; `world.skinTiles` (`"x,y" → texture name`) swaps in `gothic`/`castle` masonry, and both are read in `raycaster.js`. `isRoadTile` guards vegetation placement: `addProp` drops any tree/bush/rock that lands on a road, otherwise the forest blocks the road.
- `src/wildlife.js` — cows/goats/foxes. **Animals live in `world.animals`, not `world.actors`.** `stepAnimal` is deterministic (no clocks, no `Math.random`); `animalOnHit` returns drops; `bleedTick`/`applyBleed` drive the damage-over-time.
- `src/npc.js` — courtesan variant derived from `hashSeed(runSeed, tier, act, spot)`. **There are four courtesans keyed by spot** (`square`/`inn`/`forest`/`camp`); `world.courtesan` is only the first one, keep it as a convenience, not as the whole truth. Never persisted look: reloading and tier/act changes must reproduce the same look. Temper drives greetings, price and refusals. **`applyHeal` fills health first, then `OVERHEAL_CAP` (25)** — the courtesan is useful at full HP, so don't reintroduce a "full health" refusal. **Affinity is keyed by spot, not by variant id:** variants change per caravan, friendship must not. `applyHeal(..., free=true)` heals health but gives **no** overheal.
- `src/civilian.js` — nine non-combat NPCs in `world.civilians` (never in `world.actors`): six village roles plus `priest` (cathedral), `market_trader` (market) and `throne_guard` (town hall). `stepCivilian(person, dt, threat, moveActor, world)` is route-walking plus escape-from-titan; no perception of the player, no damage. Their collision radius is 0.85× on purpose so they can't wall off the path to the merchant — `tests/world-population.test.js` has a flood-fill guard for that. **`canStand` must skip the actor itself in the civilians loop** (`person === ignore`): without that a civilian blocks its own body and cannot move a single step.
- `src/person.js` — the 96×184 sprites for those nine roles, plus a guard test that every `CIVILIAN_ORDER` kind has an entry. The head renderer lives in `courtesan-sprite.js` (`head`, exported) — do not write a second face, or one scene ends up with two art styles. Guards, the driver and the merchant are 96×184 too and share `HUMAN_SCALE` in the renderer.
- `src/intro.js` — three procedural splash screens (`dusk`/`death`/`gold`) drawn into canvas slots in the start and end panels. Seeded and deterministic: a splash that changes between frames reads as a glitch. `tests/intro.test.js` runs them against a fake 2D context, so they are testable without a browser.
- `src/raycaster.js` — DDA walls, floor casting, billboards, weapon, suspicion bars, day/night shading. Buffer is **1280×720**; the size is duplicated in `index.html` and `SCREEN_W/H`, and the FOV plane (0.66) lives in both `player.js` and `raycaster.js`. **UI pixels are authored in 640×360 units and multiplied by `UI_SCALE`** (weapon, suspicion bars, horse head, crosshair via the `--pixel` CSS variable) — raw pixel offsets now look half-size. **Camera height and pitch are shear, not rotation:** `jumpZ` divides by depth (`(SCREEN_H*0.5 ± jumpZ)/perpDist` for walls, `/transformY` for sprites) — a constant offset on `drawStart` detaches walls from the floor. Pitch only shifts the horizon. **Tall buildings scale `topOffset` by `world.tallTiles[mapX,mapY]` while `bottomOffset` stays on the floor**, and the texture step is `TEX_SIZE * perpDist / SCREEN_H` so the masonry keeps its scale instead of stretching. The gable roof is skipped when `tallMul > 1.5` — on a nine-tile tower it becomes a black band across the screen. **Floor, walls and the finishing pass run in 2×2 blocks** (`y += 2`, `x += 2`, one sample written to all four pixels): at 1280×720 the full-resolution loops cost ~55 ms/frame, blocks bring it to ~15. `finishFrame` uses precomputed vignette and grain tables — recomputing them per pixel is the single most expensive mistake available here. **`SPRITE_MAX_DIST` (26) drops sprites before the sort**: in the forest 475 of 496 sprites were drawn every frame, and that was the "lag near the forest" bug. **Never use `ctx.filter` here** — `shadedSprite()` caches darkened copies instead, because `ctx.filter` is software rasterisation in Chrome. Sprite height is `SCREEN_H / depth * scale`, so the composited sprite canvas size does **not** affect on-screen height.
- `src/ray.js` — pure single-ray DDA (`castRay`), tested in `tests/ray.test.js`. **A missed ray must return `dist = MAX_RAY_DIST`, never `0.05`.** The old inline version treated "no hit" as "wall in your face", which stretched a wall over the whole screen once the map grew past 80 tiles per ray. The step budget is derived from the map diagonal, not a magic number.
- `src/dither.js` — Bayer dithering, deterministic grain, vignette, wall AO, murk tint. Pure. `DITHER_LEVELS = 16` with `ditherStrength = 0.28`; raising the strength turns the frame into visible dots (this happened once — screenshot before shipping).
- `src/lighting.js` — lightmap (`Float32Array`), point lights, `sampleLight` with bilinear interpolation, flicker. `buildLightmap(world, ambient, time)` is **no longer called every frame**: rebuilding it means filling 40 000 tiles plus every light radius, which costs more than the whole raycaster. `main.js` refreshes it 10×/sec and on phase change (`game.lightTimer`). `sampleLight` must stay closure-free — it sits on the per-pixel floor path. **`worldLights` coordinates are absolute after the +40 shift**; the old village torches lit empty fields for a long time because nobody checked. **Sprites are darkened through `Renderer.shadedSprite()`, not `ctx.filter`** — `ctx.filter` forces software rasterisation in Chrome and ran per sprite per frame; the cache holds 8 brightness steps per sprite key. Do not reintroduce `ctx.filter` in the sprite loop.
- `src/weather.js` — rain and snow derived from `runSeed` only. **Never derive weather from current time or `Math.random`**, or reloading a checkpoint becomes a "make it dry" button. `stepWeather` ramps intensity smoothly; `dropPosition`/`snowflakePosition` are deterministic from index + time so particles don't jump between frames. `SNOW` is kept in `kind` via `targetKind` — recomputing kind from intensity alone would silently turn snow into drizzle.
- `src/cheats.js` — dev console parser/executor, pure and tested. **Intentionally available without `?debug=1`**; the overlay labels itself as developer mode. `cheatContext()` in `main.js` wires `setTier`/`setAct`/`setWeather`.
- `src/advice.js` — `objectiveOf`/`progressOf`/`adviceFor`, pure. Panel is the sixth overlay: it must be in `canControl()` and in the `Escape` chain.
- `src/courtesan-sprite.js` — four 96×184 styles keyed by spot (`ball`/`business`/`gothic`/`road`), plus a `bloodied` variant. Every style predraws its own `make()`; importing the one from `sprites.js` is not possible (module order). Sprites are cached as `<key>_clean` / `<key>_blood` — delete stale keys or they accumulate every caravan.
- `src/horse.js` — mount/dismount rules and terrain speed. **`horseMultiplier` must stay separate from `speedMultiplier`** (the cheat console writes the latter; multiplying them would let `speed 5` + horse reach ×60). Mounted state from `game.mounted` is deliberately **not** persisted: actor positions aren't saved, so a mounted save would have no horse on reload. Mounted blocks stealing, blocking and crouching — enforced in `updateGame`, `player.update` and the `E` handler.
- `src/titan.js` — the titan: slow unkillable hunter plus three philosophy questions. **It must never eat `merchant` or `courtesan`** (`IMMUNE_KINDS`) or the run becomes unwinnable; `tests/titan.test.js` guards that. Lives in `world.titan`, not `world.actors`, so `spawnCamp` and the enemy dispatcher ignore it. `run.titanPacified` is persisted — without it F5 replays the dialogue. Death by titan uses `titanDeath()` (full run restart), not `die()`. **`stepTitan(titan, prey, dt, moveActor, world)` must receive `moveActor` and the world** — it used to write `x`/`y` directly and walked straight through houses on its way to the player. `TITAN_AGGRO_RANGE` (16) bounds its interest: without it the titan crossed the whole map to the nearest peasant and cleared the population. After losing a target it idles for `TITAN_ROAM_TIME` before picking a new one, so it can't chain-eat in consecutive frames. Civilians panic when the titan is within `CIVILIAN_PANIC_RANGE`, which is why `stepCivilian` takes an optional threat — do not drop it, or the whole population stands still and gets eaten.
- `world.js`'s `isWallTile` is the single source of truth; `ray.js` re-exports it. Adding a tile means editing `TILE`, `isWallTile`, and `textures.walls` together — `tests/ray.test.js` has a guard for wall tiles without a texture. `TILE.BRICK_FRAME = 6` and `TILE.PLASTER_FRAME = 7` are the fachwerk facades.
- `src/enemies.js` — guard/driver AI. Calls `game.damagePlayer` and `game.onGuardAlert`, assigned in `main.js` at module scope. `updateActors` takes a small context object, not the whole `game`. Guards have `lastSeenX/Y` and a `search` state; don't remove the search branch without replacing the escape mechanic.
- `src/style.js` — style telemetry → archetype → tuning. All multipliers are clamped by `TUNING_CAPS`; never let them escape, that's what keeps the game from punishing skill.
- `src/contracts.js` — deterministic per-run/act/offer seed. `generateContracts` → 3 offers; `checkContract` is evaluated against a snapshot from `main.js`.
- `src/profile.js` / `src/save.js` — meta progression and the single `corovans.save.v1` autosave slot. `migrateProfile` must always return a valid profile.
- `src/rng.js` — `createRng(seed)` with saveable `state()`. All randomness in game logic must go through it; `Math.random` breaks save/restore determinism.
- Pure, DOM-free logic (imported by Node tests): `inventory.js`, `economy.js`, `combat.js`, `world.js`, `rng.js`, `style.js`, `contracts.js`, `profile.js`, `run.js`, `daynight.js`, `motion.js`. Browser-only: `main.js`, `ui.js`, `audio.js`, `input.js`, `textures.js`, `sprites.js`, `raycaster.js`, `save.js`.

## Gameplay state quirks

- `world.campGuards` is a subset of `world.actors` that includes the driver despite the name; `village_guard` and `merchant` are separate fields. `world.dormantGuards` holds sleepers.
- `world.wagonLooted` blocks repeat looting. `spawnCamp(world, tier, tuning)` resets it and rebuilds guards/driver. Respawn is scheduled in `main.js` after loot is sold and postponed while the player is within 13 units of the wagon.
- Stealing requires holding `E` within 2.5 of the wagon; releasing `E` or leaving range resets progress, damage does not. While stealing, `player.update` is skipped but AI still runs.
- Blocking is `input.isBlocking()` → `player.blocking`; `combat.blockAbsorb` handles it in `damagePlayer` (front-only, costs 1.2× damage in stamina, 25% absorb when broken). Blocking disables attack and skips stamina regen. Landing a jump sets `noiseTimer`, which can wake sleepers — `wakeSleepers(world, x, y, radius)` is radius-based on purpose.
- `enemies.js:updateActors` dispatches **by explicit species**. There is no `else` fallback: an unknown kind is left alone. Adding an animal to `world.actors` would make it patrol and attack like a guard — keep animals in `world.animals`.
- Killing an animal must **not** add wanted level or act style "kill"; only humans do that. `performAttack` skips `merchant` and `courtesan` — the courtesan must never be a valid target.
- `run.bleed` is persisted in the snapshot. If you add a damage-over-time effect, add it to `snapshotRun`/`restoreRun` too, otherwise reloading heals it for free.
- `player.overheal` (0..25) is also persisted via `run.player.overheal`. Damage goes through `absorbWithOverheal` in both `damagePlayer` and `applyBite`; it decays only while moving (`player.update`). If you add another damage path, route it through the same helper or the buffer stops protecting the player.
- `run.courtesanAffinity` is persisted too, keyed by spot. **Do not key it by variant id** — the look is regenerated every caravan, so friendship would silently reset and look like a bug. Only paid visits raise it; free ones must not, otherwise one free visit makes her free forever.
- Any new overlay must be added to `canControl()` **and** to the `Escape` handler. The courtesan panel is the fifth overlay; forgetting it lets the player walk around inside a dialogue.
- `run.wanted` comes from witnessed thefts and kills; the village guard turns hostile above 0. The merchant clears it for a fee.
- **Checkpoints only block during an active steal.** Do not gate saving on `wanted` or an active chase: guards spot the player almost immediately after a theft, and the run would silently stop saving. Actor positions/HP are never persisted, so reloading cannot reroll a camp.
- `die()` is a soft death: reload the checkpoint, then apply −20% gold and drop all carried loot, then write a new checkpoint **so the penalty can't be undone by reloading**.
- Losing pointer lock pauses the game. Trade/help/loot set `game.uiOpen = true` before `exitLock()` to suppress that; `ui.tradeOpen`/`helpOpen`/`lootOpen` are derived from DOM `hidden` classes and gate `canControl()`.
- Victory needs `run.gold >= goalOf(run)` **and** `run.totalSold > 0`; `totalSold` grows only on sales, not caravan coin. Three acts: 300 → 800 → 1500.
- Player spawn `(7.5, 24.5)`, camp wagon `(30.3, 8.1)`; route is east along the road, then north.

## Verification

`npm run verify` covers syntax plus 221 unit tests: RNG determinism, style caps, contract pass/fail per type, profile migration, save/restore, checkpoint rules, soft-death math (rounded up, so "20%" is not a lie), camp archetypes, day phases, jump physics, pitch clamping, block absorb, wildlife behaviour and drops, bleed ticks, courtesan variants, map reachability (flood-fill spawn → merchant → courtesan → wagon, plus cathedral, town hall, market and hovel quarter), ray geometry (no false hits, no screen-filling walls), dithering and lightmap math, weather determinism and ramps, courtesan tempers, overheal and affinity, civilian population and panic behaviour, titan walls/aggro range/eating rate, splash screens, cheat console, advice hints, titan prey immunity, horse mount rules, map collision and LOS.

`tests/logic.test.js` asserts exact map coordinates, guard counts (`tier + 1`) and HP formulas — changing the map or tier scaling means updating those assertions in the same commit.

Manual smoke test with `?debug=1`: start → walk east/north → hold `E` at the wagon → pick loot → sell at Mardo → take a contract → wait for the next caravan; then reload and check «Продолжить» restores gold and the contract, and that death costs 20% but keeps reputation.

## Gotchas

- Git commands fail with "dubious ownership" for `E:/Corovans`; run `git config --global --add safe.directory E:/Corovans` first.
- **Never bind `Ctrl`.** `Ctrl+W` closes the tab and cannot be cancelled by `preventDefault()`, so crouch is `C` (hold) and `Ctrl` is deliberately unused. Space is jump, not attack; attack is LMB only.
- `player.jumpZ` is a getter over `player.jump.z`; assigning to it throws in ES-module strict mode. Mutate `player.jump`, or use `requestJump()`.
- `audio.init()` and `input.requestLock()` only work inside a user gesture (start button click); don't call them from module scope.
- `localStorage` may be unavailable (private mode); the game must run without saving rather than crash.
- Headless smoke checks run in a **fresh temp profile**, so they never expose stale-module caching. When a user reports "the fix isn't there", verify the served bytes (`fetch` the module and check for the new symbol) and the `build` stamp before touching code. `python -m http.server` returning `304` for `src/*.js` is the classic cause.
- **Logic tests do not cover rendering.** A green `npm run verify` once shipped a screen-filling wall artifact. Rendering changes need a pixel check: capture the canvas and assert no column band is a flat grey run (`visual.mjs`-style check), plus screenshots at several map points. Pure-geometry regressions belong in `tests/ray.test.js`.
- The canvas is scaled by an **integer factor** in `main.js:applyCanvasScale` (640×360 → 1280×720 at 2×). Non-integer scaling with `image-rendering: pixelated` blurs the picture; don't reintroduce `width: 100%` on `#game`. Expect black bars on non-multiple screens.
